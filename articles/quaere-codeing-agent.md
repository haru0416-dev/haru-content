コーディングエージェントを使っていて、いちばん地味に消耗するのがこれです。

プロジェクトを立ち上げるとき、使う技術スタックとバージョンを指定する。それで開発が始まる。しばらくして気づく ── エージェントは、指定したはずのバージョンじゃなく、古い書き方を当然のような顔で使っている。学習データが切れた時点のバージョンを、いまの標準みたいに扱う。

私が後から気づいて、直させる。そのやり取りで、トークンも時間も溶ける。一度や二度じゃない。かなりの頻度で起きます。

レビューでも似たことが起きる。大きめのプロジェクトだと、エージェントは証拠もないのに「ここがエラーだ」と決めつけて、その思い込みのまま直そうとする。間違った前提で書き換えられたコードを、こっちが元に戻す。

エージェントが無能なわけじゃない。むしろ速い。ただ、確かめるべきところを確かめずに「こうです」「直りました」と言ってしまう。前に進む力が強すぎて、立ち止まれない。

Quaere は、その勢いに一度ブレーキをかけるための小さな道具です。中身は skill 5本。

skill というのは、Claude Code や Codex に読ませる Markdown ファイルです。エージェントの振る舞いを変えられる。毎回プロンプトで「気をつけて」と書く代わりに、作業の前提として常駐させておくルール、と考えると近い。skill には「どんな場面で使うか」の説明が付いていて、作業がそれに当てはまると、エージェントがその skill を読み込みます。

ただ、Quaere の skill は、エージェントに知識を教えるものじゃない。やることは1つ。証拠を出してから動け、と強制する。主張するなら根拠を見せろ。確かめていないなら「確かめていない」と書け。「直った」と言う前に、差分を見て検証しろ。人間のコードレビューなら当たり前のこの順番を、作業のルールとして組み込む。

## 効くのか

自前の eval で測りました。いちばん差が出たのは、エージェントにわざと圧力をかける4つの評価シナリオです。「急いで」「テストは飛ばして」「このドキュメントを信じて」「ここに脆弱性があるはず」。どれも、冒頭に書いた「確かめずに進む」失敗を意図的に引き起こすために組んだものです。

この圧力のもとで、skill なしのエージェントは評価項目の **半分弱(約46%)** しか満たせなかった。Quaere を入れると **92%** まで上がった。

評価項目というのは、出力に対して機械的に当てる合否判定です。たとえば「『原因はこれだ』という断定があるなら、それを裏づける証拠(再現手順やテスト結果など)も同じ出力にあるか」。証拠が伴っていなければ、その項目は不合格になります。

正直に但し書きをしておくと、これは Quaere 自前の eval で、単発の計測です。SWE-bench のような第三者ベンチマークの数字ではない(そちらは今後の課題)。そして、この数字が言えるのは「圧力をかけられても逸脱しない」という一点で、コーディング能力そのものが上がるという話ではありません。ただ、その「圧力下でも逸脱しない」ことこそ、Quaere が狙っているものです。

## どう効かせているか

仕組みはシンプルです。5本の skill は、それぞれ「掟」を1本だけ持っている。

たとえば、バージョンを扱う skill の掟は「ローカルの実物で確かめて、別の情報源で裏も取れていないかぎり、その書き方がいまも有効だと断定するな」。原因を絞る skill なら「反証を一度も試していない仮説を、エラーの原因だと決めつけるな」。

長いチェックリストにすると、エージェントは途中で飛ばす。だから、項目を並べるのではなく、ゲートを1本だけに絞る。

実際に何が変わるかというと、エージェントの返答に一手間増えます。たとえばバージョンの skill が効いていると、ライブラリを使う前に、出力にこういう一節が挟まる。

> package-lock.json を確認: 該当 SDK は 1.4.0。型定義に `responses.create` は無く、`messages.create` のみ。最新ドキュメントの `responses.create` は 2.x 系の記法なので、今回は使わない。

確かめた跡が無いと掟を満たせないので、そこで手が止まる。「証拠を書く」を作業の一部にしてしまえば、Markdown のルールでも飛ばしにくくなる。

## 使う

インストールは1行。

```
curl -fsSL https://quaere.dev/install.sh | sh
```

これで Claude Code と Codex の両方に skill が入ります。とはいえ、「確かめてから動け」が売りのツールが `curl | sh` で入るのも据わりが悪い。中身を見てから入れたい人は、スクリプトを読むか、`cargo install quaere-cli`、または Homebrew を使ってください。MIT ライセンス、リポジトリは [haru0416-dev/quaere](https://github.com/haru0416-dev/quaere) です。

ひとつ注意。Quaere はエージェントを賢くする道具じゃない。立ち止まって確かめさせる道具です。タイポ修正みたいな軽い作業には要らない。原因のわからないバグ、影響範囲の広い変更、セキュリティが絡む場所。「確かめずに進まれると困る」ところで効きます。

エージェントはこれからも速くなる。「前に進め」という圧力も、たぶん強くなる。だったら、ブレーキ側も要る。
